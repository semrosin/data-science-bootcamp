# Поиск кандидатов для объявлений услуг

Решение создаёт `answer.csv` для задания из [`task.md`](task.md). По каждому
поисковому запросу оно возвращает 50 идентификаторов объявлений из корпуса.
Модель и все вычисления выполняются локально, без внешнего API.

## Метод

1. Для заголовков объявлений строится TF-IDF индекс символьных 3–5-грамм.
   Он устойчив к словоформам и небольшим опечаткам в коротком запросе.
2. Для заголовка, начала описания и параметров объявления строится отдельный
   словный TF-IDF индекс. Длинные описания обрезаются, чтобы повторяющиеся
   рекламные блоки не вытесняли сведения об услуге и не раздували память.
3. По обучающим парам строится второй индекс запросов. Ближайшие к новому
   запросу тексты голосуют за подкатегории услуг. Вероятности пяти ведущих
   подкатегорий мягко увеличивают оценки соответствующих объявлений.
4. Пары из train также показывают, в каких локациях пользователи выбирают
   объявления при поиске из заданной локации. Этот сигнал охватывает соседние
   города и области. Для локальной проверки переходы считаются только по
   объявлениям вне корпуса бенчмарка: проверяемая пара не может попасть в
   географическую статистику.
5. Смешиваются текстовые оценки (`title_weight=0.2`), затем применяются
   географический множитель (максимум `30`, степень `0.4`) и поправка за
   подкатегорию (максимум `4`). Результат — 50 лучших `item_id`.

Используются открытые библиотеки PyArrow, NumPy, SciPy, scikit-learn и LightGBM.
Нейросетевые модели и внешние сервисы не применяются.

## Обучаемое ранжирование

Для запросов, текст которых отсутствует в обучающей выборке, решение сначала
отбирает до 300 объявлений прежним разреженным поиском и до 100 дополнительных
по совпадению текста фильтра. Затем LightGBM
ранжирует их по текстовым и географическим оценкам, категории, числу отзывов,
другим свойствам объявления и совпадению текста поискового фильтра с описанием.
Обучение использует исторические пары из `train.parquet`, чьи объявления есть
в корпусе; прямое совпадение текста запроса исключается из категорийного
приоритета при подготовке обучающих признаков. Для уже встречавшихся запросов
сохраняются первые 40 объявлений прежнего поиска. До 10 остальных мест
заполняет отдельный ранжировщик, который учитывает точный категорийный
приоритет и поисковый фильтр. Для него из обучающих примеров исключаются все
тексты таких запросов из бенчмарка. Ответы для запросов с новым текстом
остаются теми же, что в предыдущей версии.

Для известных текстов проведена отдельная проверка на двух непересекающихся
выборках по 800 текстов. Их собственные тексты удалены из обучения ранжировщика;
результаты взвешены по частоте текста и наличию фильтра среди 916 известных
запросов бенчмарка. Recall@50 составил **0,8236 → 0,8435** и
**0,8499 → 0,8868**. На 62 исторических парах с точно теми же текстом,
локацией и фильтром, что у запросов бенчмарка, он составил **0,8387 → 0,8871**.
Это локальная проверка: она не гарантирует прироста на скрытой разметке.
Повторить её можно командой
`python evaluate_known.py --dataset dataset`.

В проверочном эксперименте на 800 отдельных запросах с фильтрами прежний
поиск получил Recall@50 0,8436, а обучаемое ранжирование — 0,8928.
На другой отложенной выборке из 800 запросов разных типов оценки составили
0,8417 и 0,8660 соответственно. Это локальные оценки на исторических парах,
а не результат скрытой проверки.

## Воспроизведение

Решение проверено на Python 3.14.2.

Положите `train.parquet`, `benchmark_items.parquet` и
`benchmark_queries.parquet` в `dataset/` рядом с `solution.py`, затем из корня
репозитория выполните в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe solution.py --dataset dataset --output answer.csv
```

Для запуска тестов установите зависимости разработки:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.pytest_tmp
```

Параметры модели фиксированы. `--validation-size 0` пропускает локальную
оценку и формирует тот же файл быстрее.

На локальной выборке из 1 200 разных нормализованных текстов предыдущая
версия получила Recall@50 **0,7324**, новая — **0,8249**. При оценке текст
запроса, включая варианты с другими пробелами и регистром, исключается из
обучающих примеров для предсказания подкатегории. Это оценка на исторических
парах, чьи объявления попали в текущий корпус; она не является результатом
скрытого бенчмарка.

Итоговый `answer.csv` дополнительно проверяется программно: ровно один ряд на
каждый `query_id`, только две требуемые колонки, до 50 уникальных и
существующих в корпусе `item_id` в строке.
