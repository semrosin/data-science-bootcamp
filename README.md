# Поиск кандидатов для объявлений услуг

Решение создаёт `answer.csv` для задания из [`task.md`](task.md). По каждому
поисковому запросу оно возвращает 50 идентификаторов объявлений из корпуса.
Модель и все вычисления выполняются локально, без внешнего API.

## Метод

1. Для заголовков объявлений строится TF-IDF индекс символьных 3–5-грамм.
   Он устойчив к словоформам и небольшим опечаткам в коротком запросе.
2. Для заголовка, начала описания и параметров объявления строится отдельный
   словный TF-IDF индекс. Длинные описания обрезаются, чтобы повторяющиеся
   рекламные блоки не вытесняли сведения об услуге и не раздували память.
3. Косинусные сходства двух индексов смешиваются. Объявления из локации
   запроса получают мягкий множитель; объявления из других локаций тоже могут
   попасть в топ-50 при сильном совпадении текста.
4. Вес заголовка и множитель локации выбираются по Recall@50 на 1 500
   исторических запросах из `train.parquet`, для которых выбранное объявление
   присутствует в `benchmark_items.parquet`. Берётся не более одного контекста
   на текст запроса. Случайное зерно фиксировано (`42`).

Используются открытые библиотеки PyArrow, NumPy, SciPy и scikit-learn.
Нейросетевые модели и внешние сервисы не применяются. Другие признаки
объявления, в том числе цену и рейтинг, мы не использовали: для первого этапа
поиска важнее не отсеять подходящее объявление. Почти все обучающие запросы
находятся в одной категории, поэтому категория не применялась как фильтр.

## Воспроизведение

Положите `train.parquet`, `benchmark_items.parquet` и
`benchmark_queries.parquet` в `dataset/` рядом с `solution.py`, затем из корня
репозитория выполните в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe solution.py --dataset dataset --output answer.csv
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.pytest_tmp
```

Для повторного запуска без настройки весов можно передать
`--validation-size 0`; в этом режиме используются фиксированные веса по
умолчанию, поэтому полученный CSV может отличаться.

На локальной настроечной выборке из 1 500 разных текстов лучший вариант
(`title_weight=0.15`, `location_multiplier=60`) получил Recall@50 **0,7304**.
Это оценка на исторических парах, чьи объявления попали в текущий корпус; она
не является результатом скрытого бенчмарка и может быть смещена. На другой
случайной выборке из 1 000 текстов тот же вариант получил **0,7380**.

Итоговый `answer.csv` дополнительно проверяется программно: ровно один ряд на
каждый `query_id`, только две требуемые колонки, до 50 уникальных и
существующих в корпусе `item_id` в строке.
